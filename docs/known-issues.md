# 已知问题与待验证项

适用版本：v1.3.1。以下项目来自源码检查和虚构状态验证，尚未修复；本次文档更新不改变程序行为。不包含真实账号、聊天、运行日志或本机路径。

## 待修复

| 优先级 | 问题及触发条件 | 影响与核实方式 |
| --- | --- | --- |
| 高 | 已恢复运行的任务取消托管后，记录仍可能保持 `resumed`（已继续）状态；未托管检查只覆盖 `observing`（观察中）状态 | 额度降低后，该任务仍可能被自动暂停。已用虚构数据复现：取消托管、确认不在管理范围后，下一次判断仍返回暂停。 |
| 高 | 选择“五小时和周额度”，但服务未提供周剩余额度 | 自动恢复判断可能将未知的周额度视为通过，不符合两项都满足恢复条件的设计。已用虚构数据复现。 |
| 中 | 程序窗口已打开，但后台监控已停止；通过 MCP（模型上下文协议）登记继续 | 桥接层尝试再次启动托盘程序，已有窗口的单实例逻辑使新进程直接退出，无法可靠唤醒后台。根据两处启动逻辑核实，窗口中的继续按钮与此入口不同。 |
| 中 | 重启客户端后，已托管的原聊天尚未加载 | 后台只能处理已发现控制端的聊天，没有自动打开这些聊天的补偿流程，可能持续等待手动加载。根据聊天发现、状态读取和界面打开聊天的调用位置核实。 |
| 中 | 启动、设置保存或界面控制发生错误 | 部分错误仅进入隐藏的文本缓冲区；完整日志窗口主要读取事件文件，未完整覆盖这些界面错误，用户可能看不到具体失败原因。根据错误写入及日志读取路径核实。 |
| 低 | 主界面截图、任务数量展示与当前操作范围不完全一致 | 仓库主界面图尚未更新判断依据及自动恢复标识；执行中数量包含未托管聊天，可能被误解为全部是托管任务。已检查图片与计数来源。 |

优先处理前两项，以确保取消托管后真正解除控制，以及未知额度不被当作检查通过。以上条目只有在修复与验证完成后才会标记为已解决。

## 尚未完成的真实验收

当前已进行模拟额度及状态机检查，并验证过真实任务的暂停、手动继续。新版完整跨越服务端额度重置后的无人干预自动续跑，仍缺一次真实完整周期验收；不能用模拟通过替代这项验收。

## 当前已实现的策略

- 判断依据可选择仅五小时、仅周额度或双项判断；双项模式按“任一低于暂停线则暂停、两项均达到自动恢复线才自动恢复”设计。
- 自动恢复阈值只用于自动续跑。手动继续要求所选额度高于暂停阈值，并通过服务端与任务状态检查。
- 自动续跑和使用已有重置卡可分别控制；重置卡默认关闭，不自动购买额度。
- 上述行为仍受本页列出的已知例外影响。客户端协议兼容及轮询延迟等一般限制见主说明。
