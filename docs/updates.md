# 版本更新

## 老版本如何升级

v1.4.1 及以前没有内置更新入口。请从本项目 GitHub 发布页手动下载一次 v1.5.0 或更新版本，退出旧程序并替换 EXE。本地数据目录保留即可沿用设置与托管记录。

## 新版检查与安装

- 默认在启动时和运行期间每天检查公开更新清单；该选项可以关闭。
- 发现新版显示提醒，并在主界面右上角提供更新入口。设置中使用同一个按钮：未发现新版时为“检查更新”，发现新版后切换为“一键更新”。
- 自动检查只提醒；点击“一键更新”才下载、校验并安装。
- 无需填写 GitHub 密钥，不上传额度、任务或账户数据。优先使用仓库公开的 update.json，公共 API 作为备用。

## 保留与回退

下载和校验期间继续运行当前版本。安装时停止后台并退出；更新仅替换程序 EXE，设置与任务状态文件不清除。原来停止监控的，安装后仍停止；人工保持暂停的任务不会因更新而解除。

来源必须为本仓库发布包，并核对 SHA-256 及程序版本。更新前保留旧 EXE，新版未能完成启动确认时自动恢复旧 EXE并重新打开。下载或校验失败不会覆盖当前程序。

回退针对安装及启动失败，不表示所有后续运行或客户端协议错误都会自动回退。网络不可用时可稍后重试，或手动下载发布包。

## 维护发布

发布稳定版本并上传运行 ZIP 后，维护者同步仓库根目录 update.json：tag_name、对应 ZIP 下载地址及实际 SHA-256。清单沿用 GitHub 发布元数据结构，不能指向其他仓库或未经校验的文件。不要把用户本机的 settings.json、state.json 或 updates 目录打进发布包。
